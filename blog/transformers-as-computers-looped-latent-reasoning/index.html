Transformer 是一种反复堆叠“跨位置读取”和“逐位置变换”的神经网络架构。本文把它当作一台计算机来观察，但这里的“计算机”只是一套用于拆解能力的类比：我们关心数据怎样移动、状态存在哪里、计算路径怎样选择以及何时停止；并不主张普通 Transformer 已经拥有中央处理器（Central Processing Unit，CPU）的指令集、随机存取内存和操作系统。

Token 是模型一次处理的离散序列单位；一段文字通常被切成词或词片段，每个 token 再被表示为向量。这个视角有一个很有吸引力的起点：把注意力（attention）看成数据读取与路由单元，把前馈网络（Feed-Forward Network，FFN）看成写在参数里的长期记忆；再把混合专家（Mixture of Experts，MoE）和稀疏注意力（sparse attention）看成条件分派。MoE 为一个 token 从多组候选参数中选择少数组进行计算；稀疏注意力只让一个 token 读取全部候选位置中的一部分。二者都不包含任意程序跳转，但让计算路径开始依赖输入，就像程序有了受约束的分支。接下来很自然会问：如果分支已经有了，循环在哪里？模型能否根据问题难度，多执行几轮内部计算，而不是永远穿过固定数量的层？

我的结论是：这个类比抓住了重要方向，但需要三处校正。

  1. 注意力更像“按内容寻址的数据搬运”，不是完整的指令执行单元。
  2. FFN 权重更像推理期间只读的长期记忆，不是可随时改写的工作内存。
  3. MoE 与稀疏注意力提供的是受约束的条件路由，不是任意程序跳转。

校正之后，循环 Transformer（looped Transformer）仍然是一条非常自然的路线。隐藏状态（hidden state）是模型在处理中间阶段保存、尚未转换成最终输出的向量。本文所说的循环 Transformer，是把同一组层在网络深度方向重复使用，使隐藏状态经历多轮更新；它不包括仅仅沿文本时间顺序逐 token 生成，也不等于把 32 个互不共享参数的层静态堆叠起来。它的作用，是把“计算多少步”从一次性写死的结构，变成可以复用、甚至可以按输入调整的过程。

1. 先把“像计算机”说准确

1.1 Attention：更像数据路由，不是执行全部指令

注意力让当前位置生成一个查询向量，再用它与其他位置的键向量计算相关性，最后对相应的值向量做加权汇总。查询、键和值都是从当前隐藏表示线性变换得到的向量。它解决的问题是：当前 token 应该从哪些位置取回多少信息？

因此，注意力确实有“执行单元”的一面：它动态决定数据依赖，能够复制、匹配、聚合和移动信息。但传统处理器的执行单元还要解释操作码、改变程序计数器、执行算术并处理异常；注意力本身没有这些明确接口。Transformer 中的算术和非线性变换通常由 FFN、线性层与残差更新共同完成。

更稳妥的说法是：注意力是内容寻址的读取与通信机制。 “内容寻址”表示读取位置由当前向量与候选向量的相似度决定，而不是像数组那样只用一个离散地址。它包含跨 token 的数据交换，不包含一般意义上的任意写入、跳转和停止。

1.2 FFN：像参数化记忆，但不是运行时内存

FFN 对每个 token 分别执行两次线性变换和一次非线性激活。Geva 等人在 *Transformer Feed-Forward Layers Are Key-Value Memories* 中发现，第一层的神经元模式可以像“键”一样匹配输入，第二层则输出相应的“值”；越靠后的 FFN 越倾向产生可直接影响词分布的语义模式。

这支持“FFN 是记忆”的直觉，但这里的参数化记忆（parametric memory）是训练后固化在权重中的统计关联。它包含模型从训练数据学到、可被输入触发的长期知识；不包含一次推理中随意新增、覆盖或删除一条记录的能力。普通推理只读取 FFN 权重，并不为每个用户现场改写它们。

一台实用计算机还需要工作状态（working state），即当前计算过程中会持续变化、任务结束后可以丢弃的信息。Transformer 的残差流承担了一部分角色：它是在层与层之间传递的稠密向量。上下文和键值缓存（Key-Value Cache，KV Cache）也保存已经处理过的 token 表示，以便自回归生成（autoregressive generation）时重复读取；自回归表示每次根据已经生成的序列预测下一个 token。KV Cache 通常只能随新 token 追加，并通过注意力访问，不是可以任意覆盖地址的随机存取内存。

2. MoE 与稀疏注意力：像分支，但分支的对象不同

条件分派（conditional dispatch）是根据当前数据选择有限计算路径。它包含“不同输入经过不同子模块”，不包含任意修改执行地址。用这个定义看，MoE 与某些稀疏注意力确实给 Transformer 加入了分支味道，但二者选择的对象不同。

2.1 MoE 选择“由谁计算”

MoE 在一个位置准备多个专家网络，再由路由器（router）根据当前 token 的向量计算选择分数，并挑出少数专家。这里的专家（expert）通常是结构相同、参数不同的 FFN；它不是一个完整模型，也不天然对应人类可读的技能。激活参数（active parameters）是一个 token 实际经过的专家参数，不包括本次未选中的专家。Switch Transformer 将每个 token 路由给单个专家，以保持每 token 计算量近似不变，同时扩大总参数容量。

它像下面这种受限分支：

text
if router(x) == expert_3:
    x = FFN_3(x)
else if router(x) == expert_7:
    x = FFN_7(x)

但这个分支只在预设专家集合中选择参数，不会跳到任意代码，也不会决定把同一专家重复执行多少次。它回答“由谁处理”，不回答“处理多久”。路由还带来负载不均衡、跨设备通信和专家容量溢出等系统问题，因此总参数更多不等于推理自动更快。

2.2 Sparse Attention 选择“从哪里读取”

稀疏注意力（sparse attention）只计算完整注意力矩阵中的一部分连接，以降低长序列的计算和显存成本。它包含局部窗口、固定跨步连接等预先规定的稀疏模式，也包含根据内容动态选择连接的位置；所以不能把所有稀疏注意力都称为条件分支。

  • 固定稀疏模式对不同输入使用同一张连接图，更像预先布线。
  • 内容路由注意力（content-routed attention）根据当前查询的内容选择候选键，更接近数据依赖分支。Routing Transformer 使用在线聚类（online clustering），也就是在数据到达过程中持续把相似向量分到同一组，让相似的查询和键进入同一簇；它把注意力复杂度从序列长度 n 的平方级降到论文设定中的 O(n^1.5 d)，其中 d 是隐藏维度。

无论哪一种，它选择的是“这次读取哪些位置”，而不是“下一条执行哪段任意程序”。把 MoE 与内容路由注意力组合起来，可以同时选择计算参数与数据来源，却仍没有形成真正的循环。

3. 标准 Transformer 到底缺不缺循环

答案取决于“缺”指理论表达能力，还是工程接口。

3.1 理论上不能说 Transformer 不会循环

图灵机（Turing machine）是一种抽象计算模型：它用有限的控制状态、可读写的无限纸带和状态转移规则逐步执行计算。图灵完备（Turing completeness）表示一个形式系统在无限时间和内存等理想条件下，可以模拟任意图灵机可计算过程；它不表示有限模型在现实精度、时间和显存中能可靠学会任意程序。Pérez 等人证明，Transformer 在论文规定的理想化假设下可以达到图灵完备。因此，“没有显式循环层，所以 Transformer 原理上不能执行循环”并不成立。

更现实的限制是：普通模型把深度固定在架构中。一个 32 层 Transformer 对简单 token 和困难 token 通常都执行这 32 层；层与层参数不同，也没有公开的 while condition 接口把同一状态送回同一计算块。模型可以在固定深度里模拟局部迭代，也可以通过生成更多思维 token 获得更多计算，但这两种方式分别受固定计算预算和离散语言带宽约束。这里的计算预算（compute budget）是一次训练或推理允许执行的运算总量，不包含模型参数数量本身。

3.2 缺的是“可复用、可停止、按需分配”的迭代原语

程序循环至少需要三件事：

  1. 循环状态：每轮都会更新，并传给下一轮的数据。
  2. 循环体：在多轮中重复使用的一组操作。
  3. 停止条件：决定继续还是退出的规则。

标准 Transformer 的残差流可以充当状态，一组层可以充当循环体；真正没有成为默认能力的是参数共享的回流路径和可靠停止条件。于是固定深度模型像被编译成固定次数的“展开循环”：每一轮都有独立参数，而且次数在部署前已经写死。

这一区分很重要。问题不是模型有没有足够强的数学表达能力，而是它能否以可训练、可扩展、硬件友好的方式把额外计算分配给真正需要它的输入。

4. Looped Transformer：把深度变成时间

深度递归（recurrent depth）是在网络深度方向重复调用同一组层，并让上一轮隐藏状态成为下一轮输入。它包含权重共享和状态回流，不包含沿文本时间轴逐 token 展开的普通自回归。若循环体有 m 层、重复 r 次，逻辑深度约为 m × r，但独立参数量仍主要由这 m 层决定。

4.1 Universal Transformer：共享循环体与自适应停止

Universal Transformer 在 2018 年把同一个变换块反复作用于所有位置，并可为不同位置使用自适应计算时间（Adaptive Computation Time，ACT）。ACT 是一个学习到的停止机制：它为每个位置累积继续计算的概率，达到阈值后停止更新。它包含按位置分配不同迭代次数，不保证停止信号一定对应“推理完成”。论文还在特定假设下给出了图灵完备性结果。

这已经具备循环的三个要素：隐藏状态、共享循环体和近似停止条件。困难在于，不同 token 的停止时间不同会破坏整齐的批处理；过早停止损害质量，过晚停止又失去节省计算的意义。

4.2 Looped Transformers as Programmable Computers：构造性证明

Giannou 等人的 *Looped Transformers as Programmable Computers* 用一个经过人工编程的 13 层循环 Transformer 构造出程序计数器、条件分支、函数调用、计算器、线性代数和上下文内反向传播等操作。

这是强有力的构造性结果：研究者明确给出参数和状态布局，证明循环 Transformer 可以模拟这些部件。它不等于普通语言模型经过自然语言预训练后会自动形成同样可靠的 CPU，也不证明梯度下降（gradient descent）能够轻松发现论文中的程序；梯度下降是根据损失函数对参数的导数，沿降低损失的方向反复更新参数的训练方法。构造性结果证明的是“架构容许什么”，不是“训练必然得到什么”。

4.3 Recurrent Depth：推理时真的可以多想几轮

Geiping 等人的 *Scaling up Test-Time Compute with Latent Reasoning: A Recurrent Depth Approach* 把模型分成三个部分：

text
输入 token → 前奏模块 → 共享递归核心 × r → 输出模块 → 下一个 token
                         ↑          │
                         └─ 隐状态 ─┘

前奏模块（prelude）是进入循环前执行一次的层，负责准备输入；共享递归核心（recurrent core）是重复执行、参数相同的层组；输出模块（coda）在循环结束后执行一次，把最终状态变成词概率。论文的 3.5B 参数模型用 800B token 训练，这里的 B 表示十亿；大型配置包含 2 层前奏、4 层递归核心和 2 层输出模块。当递归 32 次时，有效深度是 2 + 4 × 32 + 2 = 132 层。

训练时，作者随机采样递归次数，使模型适应不同深度，并只对最后 8 次递归保留反向传播计算图（backpropagation graph）。它记录训练中各次运算的依赖关系，用于从损失反向计算梯度；不保留更早轮次可以减少显存，但也截断了跨越那些轮次的梯度。测试时增加递归次数，部分任务的性能还能继续提高。这提供了一个很关键的工程信号：推理时计算量可以不完全由参数量和训练时固定深度决定。

论文也观察到隐藏状态轨迹会趋向固定点、形成轨道或持续漂移。固定点是多轮更新后状态几乎不再变化的位置；轨道是状态在一组位置之间周期移动。这些现象说明循环确实在形成内部动力学，但不能仅凭轨迹形状判断模型是否得出了正确答案。

4.4 Mixture-of-Recursions：分支与循环开始合并

Mixture-of-Recursions（MoR）是一种让不同 token 使用不同递归深度的方法。它复用同一层组，但由路由器决定哪些 token 在下一轮继续计算。作者讨论了两类方案：专家选择路由每轮挑选一部分 token 继续，token 选择路由则在开始时为每个 token 指定完整深度路径。

这恰好连接了本文的主线：MoE 是“选哪个专家”，MoR 是“选多少轮”。论文在 135M 到 1.7B 参数范围内测试，其中 M 表示百万；少样本准确率（few-shot accuracy）衡量模型只看到少量任务示例后答对问题的比例，不表示零样本能力或训练收敛速度。其中一个两轮配置以约少一半参数取得 43.1% 平均少样本准确率，高于同组标准模型的 42.3%。固定 token 预算的设置报告训练浮点运算少 25%、时间少 19%、峰值显存少 25%。推理吞吐（inference throughput）是单位时间内完成的 token 或请求数量；四轮模型在特定设置下最高达到 2.06× 推理吞吐，但伴随质量权衡。这些数字是论文配置内的结果，不应外推成所有硬件和任务的通用加速比。

5. Latent Reasoning：循环可以不经过文字

隐空间推理（latent reasoning）是让中间计算主要发生在连续隐藏向量中，而不是把每一步都解码成可见文字再重新输入。它包含隐藏状态的多轮变换；不保证这些状态可被人直接解释，也不等于模型没有进行计算。本文采用这个架构含义，不把任何未展示推理文本的模型都自动称为隐空间推理模型。

常见的思维链（Chain of Thought，CoT）让模型输出一串自然语言中间步骤。它有三个优点：可读、可监督、能借增加 token 获得更多推理计算。但自然语言是离散瓶颈：每一步必须先压缩成词，模型也容易把大量计算花在语法连贯上。

隐空间路线至少有两种不同实现：

  • 隐藏状态回灌：Coconut（Chain of Continuous Thought）把上一轮最后隐藏状态直接作为下一轮输入嵌入，不先选出一个词。论文报告它在需要规划搜索的逻辑任务上优于相应思维链基线，并提出连续状态可以同时保留多个候选方向。广度优先搜索（Breadth-First Search，BFS）是一种先展开当前深度的多个候选，再进入下一深度的搜索策略；不过，“像 BFS”是作者对行为的解释，不等于模型内部存在一棵可读的显式搜索树。
  • 整层组递归：Recurrent Depth 模型让整段隐藏状态穿过共享核心多轮，把测试时额外计算放在网络深度而非输出长度上。

二者都把“想一步”从生成一个语言 token 改成更新一次连续状态，但计算粒度不同。隐藏状态回灌更接近在输入槽位中加入连续思维；深度递归则在输出同一个 token 之前重复整个计算块。

5.1 隐空间推理不自动更好

它至少有五个未解决边界：

  1. 可监督性：没有中间文字，就更难直接标注哪一步错了。
  2. 可解释性：探针能读出相关信息，不代表该信息因果地决定了答案。
  3. 停止策略：相邻两轮输出趋同不保证答案正确，只表示模型不再明显改变主意。
  4. 训练稳定性：同一权重反复应用可能让状态爆炸、消失或陷入错误固定点。
  5. 硬件效率：动态轮数降低无用计算，却会让一个批次中的样本和 token 不再同步。

因此，循环加隐空间不是免费的“更会思考”。它把可见 token 的成本换成隐藏状态更新，也把可读轨迹换成更难观测的动力系统。

6. 那么 GPT-6 是否已经“专注 loop”

截至 2026 年 9 月 4 日，OpenAI 官方开发者文档已经列出 GPT-6 Astra，并公开上下文长度、输入输出类型、工具支持与推理控制等产品能力。这里的“官方事实”只表示产品页面明确写出的内容。

同一批官方页面没有披露模型内部层结构，也没有说明它采用循环 Transformer、深度递归、Coconut 式隐藏状态回灌或某种 latent loop。页面中没有足以支撑“GPT-6 最新架构专注 loop”这句话的架构证据。因此，本文不能把它写成事实。

更准确的判断分三层：

  • 已验证：GPT-6 Astra 是官方公开的模型产品，并提供可调推理能力。
  • 合理假说：循环深度能把测试时计算量与参数量部分解耦，和当前推理模型的发展目标高度吻合。
  • 尚未验证：GPT-6 Astra 内部采用某一种 loop 或 latent-reasoning 架构。

产品支持“更多推理计算”并不能反推出底层一定用循环层。它也可能通过生成更多隐藏或可见 token、调用不同模型、使用并行候选、动态层跳过，或采用未公开的混合方案实现。除非 OpenAI 发布技术报告、模型卡架构段落、专利或可复现实验，具体机制都应保持未知。

7. 离“比较完备的计算机”还缺什么

如果把目标从“生成下一个 token”提高到“执行长程序”，仅有分支与循环仍不够。

7.1 可写、可寻址、可持久的记忆

可写记忆（writable memory）是在一次任务中能够创建、更新和读取状态的存储。它包含明确的写入内容、寻址方式和生命周期；不包含只读模型权重。Neural Turing Machine 把神经网络控制器连接到外部记忆矩阵，并用可微注意力（differentiable attention）完成读写；“可微”表示读写权重可以通过梯度训练。该系统在复制、排序和关联回忆等任务上学习了简单算法。

这项工作提醒我们：FFN 记忆与程序内存不是同一件事。循环模型若没有稳定的可写状态，只能不断重编码整个残差流；长程序中的变量、栈、堆和中间产物仍难以可靠管理。

7.2 稳定控制流与错误处理

一个循环不仅要能继续，还要能正确退出。神经停止信号通常是概率，容易出现差一轮、永不停止或过早停止。现实程序还需要函数边界、异常、回滚和资源限制；这些在端到端隐藏状态里都没有天然语义。

7.3 输入输出与外部世界的事务边界

工具调用会改变外部状态，例如写文件、发消息或付款。事务边界（transaction boundary）是把一组外部操作定义成可确认、可提交或可回滚的单位。它包含权限检查、失败恢复和幂等性（idempotency）；幂等性表示同一请求即使因重试而执行多次，也只产生一次预期外部效果。事务边界不包含模型内部“觉得自己已经完成”。一个更像计算机的模型仍需要外部运行时来约束这些动作。

因此，比较完整的神经计算系统至少需要：数据路由、参数化知识、动态工作状态、条件分派、循环与停止、可写记忆、外部输入输出，以及验证和恢复机制。Loop Transformer 主要补的是循环体与状态回流，不是一次补齐整台计算机。

8. 我更看好的研究组合

从这个视角出发，下一步不应只比较“循环模型”和“非循环模型”，而应把三个独立轴组合起来：

研究轴核心问题可测指标
路由哪些 token 读取哪些位置、调用哪些专家质量、激活参数、通信量、负载均衡
递归哪些 token 需要多少轮状态更新准确率随轮数曲线、平均轮数、最慢一批请求的完成时间
记忆哪些中间状态需要写入、覆盖和取回长程一致性、写后读正确率、污染与遗忘

一个具体架构可以让共享注意力负责通信，让 MoE 提供不同类型的计算，让 MoR 为不同 token 分配递归深度，再把少量关键状态写入外部工作记忆。路由器不只回答“去哪个专家”，还要回答“是否继续”和“哪些状态值得保存”。

但实验必须防止一个常见错觉：更深递归得到更好结果，可能只是用了更多浮点运算。公平比较至少要固定三种预算分别报告：固定参数量、固定训练计算量和固定推理计算量；还应报告动态批处理后的真实延迟，而不只报告理论浮点运算。

我会优先做四组可证伪实验：

  1. 在相同推理计算量下，比较增加递归轮数与增加思维链 token，判断连续状态是否真的更有效率。
  2. 随机打乱或截断中间隐状态，检查性能是否依赖循环轨迹，而不是只依赖最后一轮。
  3. 让停止器看不到答案置信度之外的信息，测试它能否识别“稳定但错误”的固定点。
  4. 同时训练 MoE 专家路由与 MoR 深度路由，检查二者是互补，还是都在重复识别 token 难度。

9. 结论

这个计算机类比帮助我区分几种计算职责，以及尚未解决的控制问题：MoE 选择谁来算，稀疏注意力选择从哪里读，循环 Transformer 决定算多少轮，隐空间推理让这些轮次不必逐步翻译成文字；但要成为可靠的通用计算系统，还需要可写记忆、可信停止、事务边界与验证机制。

Loop Transformer 为固定深度网络引入按需计算提供了一条路线。它很可能是下一代推理架构的重要组成部分；至于 GPT-6 Astra 是否已经采用这条路线，目前公开证据还不足以回答。
