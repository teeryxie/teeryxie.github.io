多模态预训练：知识迁移、模态协同与数据配比

模态（modality）是信息的表现形式，例如自然语言文本和静态图像。本文所说的统一多模态预训练（unified multimodal pretraining），是让同一个主干模型在预训练阶段同时学习语言建模、图像理解和图像生成；它不包括先分别训练三个完全独立模型、只在部署时把它们串联起来的方案。统一训练的作用，是让三类能力共享一部分表示、参数和训练预算，从而有机会互相帮助，也可能互相争夺容量。

Junlin Han 等人的论文 *Towards Physics of Multimodal Pretraining: Knowledge Flow, Modality Synergy, Early Unification, and Recipes* 研究的正是这组“帮助与争夺”关系。论文把问题拆成四个部分：

  • 知识流（knowledge flow）：一种训练能力是否会改善另一种能力，以及这种影响沿哪个方向发生；它不等同于共享了参数，也不保证双向迁移。
  • 模态协同（modality synergy）：联合训练后的目标能力优于相同预算下的单模态基线；与之相反，模态竞争（modality competition）是联合训练让目标能力变差。二者比较的是可测量结果，不是“看起来更统一”的架构形式。
  • 早期统一（early unification）：从预训练早期就把多种模态放进同一个训练过程，让它们共同更新；它不等同于把所有参数完全共享，也不等同于只在语言模型训练完成后追加视觉对齐。
  • 训练配方（training recipe）：数据比例、参数共享方式、训练顺序和优化预算的组合。本文采用论文中的这个工程含义，不是某一个单独的超参数。

这篇论文的重要性不在于又提出一个模型名字，而在于它尝试回答更基础的问题：语言、视觉理解与视觉生成在统一训练中到底怎样相互作用？ 作者先用小规模受控实验寻找规律，再用 13.5B 参数、2T token 的模型检查规律是否能够放大。这里的 B 表示十亿，T 表示万亿；token 是模型一次处理的离散训练单位，文本通常被切成词片段，图像则被编码成视觉位置或潜变量。

比起直接采用 70/25/5，我更关注论文如何测量知识迁移的方向，并据此区分模态协同与容量竞争。这套分析可以帮助判断架构与数据预算的取舍。

1. 论文究竟控制了什么

论文研究三个训练目标。

  1. 语言建模（language modeling）：根据已有文本预测后续文本，用来学习语言知识、推理模式和文本分布。
  2. 视觉理解（visual understanding）：输入图像并输出文字，例如描述图像或回答图像问题；它主要要求从视觉信号中提取可用于语言回答的判别信息。
  3. 视觉生成（visual generation）：输入文字并生成图像；它要求模型恢复颜色、纹理、形状和空间结构等密集视觉信息。

“理解”和“生成”都处理图像，但目标不同。理解任务只需保留足以回答问题的信息，生成任务则必须重建大量像素级细节。正因为目标不同，“模型看过某个概念”并不代表它能在另一目标中直接使用这个概念。

1.1 默认模型与训练目标

作者使用 Transformer，即通过注意力机制让序列中不同位置交换信息、再通过逐位置计算模块变换表示的神经网络。受控实验的默认主干类似 Llama 3：16 层、隐藏维度 2048，语言和图像使用不同的逐位置计算分支，总参数约 2.3B，其中共享主干约 1.5B。

模型采用 Transfusion 框架：文本通过“预测下一个离散 token”的交叉熵目标训练；交叉熵（cross-entropy）在模型给正确 token 的概率较低时产生更大惩罚。图像生成则通过连续空间中的流匹配目标训练。流匹配（flow matching）是学习一个随时间变化的向量场，把噪声逐步变成数据样本；它不同于自回归生成（autoregressive generation），后者每一步都以前面已经生成的离散 token 为条件，再预测下一个 token。作者还用离散视觉 token 的自回归版本复验关键趋势，因此结论不只依赖流匹配。

默认视觉表示采用 表示自编码器（Representation Autoencoder，RAE）：冻结的视觉编码器把 224×224 图像变成 16×16、共 256 个语义 token，模型在这个潜在空间里理解和生成图像，再由解码器还原像素。论文另外测试三种视觉表示：直接图像块、理解与生成各用独立编码空间，以及离散视觉 token。它们的作用是检查知识流是否只是某种视觉编码器带来的偶然现象。

1.2 数据与评测

语言数据来自 DataComp for Language Models（DCLM），它是一套用于训练语言模型的网页文本数据与筛选配方；本文中的 DCLM 不指视觉数据。视觉数据来自约 3.5 亿组 Shutterstock 图文对。困惑度（perplexity，PPL）衡量模型对真实文本的预测不确定性，越低越好。视觉理解在监督微调后用 16 个基准评测，覆盖一般感知、知识推理、文字与图表识别，以及空间和计数等视觉中心能力。视觉生成使用组合生成、长提示对齐、图文相似度和验证集生成损失等指标。

受控实验固定随机种子（random seed）为 0；随机种子是伪随机过程的起点，相同种子让模型初始化和数据迭代顺序可重复，但不代表覆盖了其他随机起点。这有利于隔离配方差异，却也意味着多数小规模结果没有跨随机种子的方差。读者应把一致的趋势视为有力证据，但不能把每个小数点差异都当成稳定效应。

1.3 两层证据：真实数据与合成数据

真实数据实验改变一种数据的数量，同时固定另一种数据的绝对预算，用来观察跨能力影响。它能回答“在现实数据分布下是否有效”，但很难排除文本风格、概念覆盖和数据质量等混杂因素。

为进一步隔离因果关系，作者使用 CLEVR，即由程序根据场景图生成几何物体图像、描述和问答的数据集。场景中的颜色、形状、大小、数量和空间关系可以精确控制。作者从某一个训练目标中删除指定概念，同时在另一个目标中保留它；如果目标能力仍能处理该概念，才算跨目标迁移。

这两层证据互补：真实数据给出外部相关性，CLEVR 给出概念级控制实验。后者仍是合成环境，不能自动证明自然图像中的所有概念都会遵循同样规律。

2. Knowledge Flow：知识不是在三种能力之间平均流动

2.1 语言是视觉能力的通用助推器

作者固定 50B 视觉 token，在其上逐步增加语言数据，使语言占比从 0% 提高到 80%。视觉理解的四类指标都随语言比例增加而改善；条件和无条件图像生成的损失也下降。

“无条件生成也改善”是一个重要观察。它意味着收益不能全部解释成文本提示变得更容易理解。作者提出，成熟的语言表示可能编码了物体、属性和关系等较通用的世界结构，从而为视觉学习提供先验。

但这里的“通用”应限制在论文的模型、数据和指标内。实验没有证明任意语言数据都能帮助任意视觉任务，也没有把语言知识、优化正则化和额外训练步数完全分解。准确表述应是：在固定视觉预算并增加 DCLM 语言训练的这些设置中，所有被测视觉指标均受益。

2.2 视觉理解强烈帮助视觉生成，却轻微损伤纯语言

作者固定 50B 语言或生成预算，再增加视觉理解数据。视觉理解显著降低图像生成损失并改善生成评测，说明理解任务学到的物体、属性与空间关系可以成为生成的有效先验。

与此同时，纯语言指标轻微下降。论文认为原因主要是图文数据里的文字分布与纯文本语料不同。因此，这个现象既可能包含参数容量竞争，也包含数据分布改变，不能简单解释成“视觉理解天然伤害语言”。

2.3 视觉生成对语言和理解大致中性

当作者固定语言或视觉理解预算，再增加视觉生成数据时，语言与理解指标只有小幅波动，没有稳定的正迁移趋势，也没有严重崩坏。

这条结论很容易被误读成“生成没有用”。论文真正说明的是：在所测标准语言和视觉理解基准上，增加生成训练没有直接带来稳定收益。生成目标仍可能学到密集几何和纹理表示，只是这些表示不会自动映射成文字答案。

2.4 概念级实验揭示两种不同的迁移

作者把概念分成两类：

  • 低层属性：颜色与形状，直接对应局部视觉外观。
  • 结构概念：空间关系、大小和数量，需要组合多个对象或属性。

对于颜色和形状，从理解到生成、从生成到理解的零样本迁移（zero-shot transfer）都失败。零样本迁移是指目标训练流从未出现该概念，模型也不经过额外微调就直接处理它。失败说明共享主干里即使存在相关信息，目标头也无法直接调用。

结构概念则呈现非对称性：理解训练能帮助模型零样本生成空间关系、大小和数量；生成训练对理解的帮助很弱，只有计数出现少量正迁移。

作者随后把缺失概念重新加入训练，并观察 2000 步微调过程。生成中见过颜色或形状的模型，学习对应理解任务明显更快，平均准确率曲线面积提高约 0.133–0.273；理解中见过形状对后续形状生成只有小幅帮助，对颜色生成几乎没有帮助。

这揭示了“直接能力”和“潜在先验”的差别：

  • 直接能力是模型无需额外训练即可完成目标任务。
  • 潜在先验是模型内部已有有用表示，但还需要少量目标任务样本建立读取路径。

因此，视觉生成并非完全不帮助理解；它更像为低层视觉概念准备了密集底座，而不是直接提供问答能力。

3. Modality Synergy：何时协同，何时竞争

论文把统一训练中的净变化看成两股力量相加：跨模态信息可以互相正则化并建立共享结构，但不同任务也会争夺有限参数容量。为了区分它们，作者分别改变任务复杂度和参数共享位置。

3.1 简单任务是助推器，复杂任务开始争容量

作者固定 100B-token 总预算，语言和图像各占 50B，并与各自 50B-token 的单模态基线比较。

视觉任务从纯色背景、规则图案、噪声、文字渲染，逐步变成真实场景文字、视频和自然图像。简单视觉任务加入后，语言困惑度反而下降：纯色背景带来 −0.211，噪声带来 −0.183。当视觉任务变成视频和自然图像时，语言困惑度分别增加 +0.052 和 +0.075。

语言侧也有类似趋势。简单的重复字母文本给图像生成带来的损失下降，大于完整网页文本带来的下降。作者据此认为：简单任务主要提供优化正则化和共享结构，复杂任务则需要更多专用容量，竞争逐渐超过协同。

这里的“复杂度”不是一个已经严格定义的标量。论文用人工设计的数据阶梯近似任务复杂度，但没有给出可跨数据集计算的统一公式。我们可以相信这些具体阶梯中的趋势，却不应宣称“复杂度达到某个数值就必然竞争”。

3.2 共享与专用容量的取舍

一个 Transformer 层包含三类与本实验有关的组件：

  • 注意力（attention）：让一个 token 按相关性读取其他 token 的信息，决定跨位置和跨模态的信息交换。
  • 前馈网络（Feed-Forward Network，FFN）：对每个 token 独立执行非线性变换，提供大量表示容量，但不直接读取其他位置。
  • 归一化（normalization）：调整特征的尺度，使后续计算处在较稳定的数值范围。

作者比较五种共享方案。稠密模型（dense model）让每个 token 都经过同一套完整参数；这里它不表示参数更多，只表示没有按模态或路由结果选择不同专家。全部共享的稠密模型让语言困惑度恶化 +0.272，视觉生成损失恶化 +0.0537；全部拆开的模型接近两个单模态基线，既没有竞争，也失去协同。

最佳方案是：按模态拆分 FFN，同时共享注意力和归一化。 它让语言困惑度相对单模态基线改善 0.211，视觉生成损失改善 0.0168。拆开注意力后，收益明显缩小；拆开归一化也削弱收益。

一个合理解释是：FFN 承担各模态不同的计算需求，因此适合分配专用容量；注意力负责让图像与语言交换上下文，归一化让两种信号维持可兼容尺度，因此适合共享。论文的实验支持这个设计规律，但“归一化为何促进协同”仍主要是机制假说，缺少更直接的因果探针。

3.3 这个规律不依赖某一种视觉 tokenizer

视觉 tokenizer 是把图像变成模型可处理序列表示的模块；它可以输出连续潜变量，也可以输出离散编码。作者在表示自编码器、直接像素块、独立的理解/生成编码器和离散自回归编码四种方案上重复实验，均观察到协同。

这说明预先把视觉与语言映射到同一个语义空间并非协同的必要条件。共享表示仍可降低工程复杂度和表示摩擦，但任务目标与 Transformer 内部的参数共享边界同样关键。

4. Early Unification：视觉接入时机的影响

4.1 在固定 1T token 下，视觉加入越晚越差

作者固定总预算为 1T token，把纯语言预训练长度设为 0/200/400/600/800B，剩余预算再做语言与视觉各占一半的统一训练。视觉数据由图像描述和条件图像生成均分。

纯语言阶段变长，语言指标早期略有改善，但在 600B 到 800B 之间趋于饱和；大多数视觉理解指标和全部视觉生成指标则随视觉引入推迟而持续下降。

这个实验的关键是总 token 预算固定。晚统一不仅改变模型初始化，也减少了视觉参与联合训练的时间。因此它证明的是“在固定总预算下，把更多预算预先花在纯语言上不划算”，不是证明任何先训语言、后加视觉的方案都必然失败。已有强语言模型的再利用仍可能是现实工程中的成本最优方案，只是它不等于从零训练原生统一模型的能力上限。

4.2 顺序训练不等于课程学习

作者把语言、视觉理解和视觉生成分成三个独立阶段，测试全部六种顺序，同时测试保留 12.5% 旧数据的回放方案。数据回放（data replay）是在学习新阶段时继续混入少量旧任务样本，用来降低旧能力被覆盖的风险。

六种顺序几乎都不如三种目标同时训练。回放能减轻灾难性遗忘（catastrophic forgetting），也就是学习新任务时旧任务能力显著下降，但仍无法恢复联合训练产生的协同。

这说明联合训练的价值不仅是“旧能力不丢”，还包括不同目标在同一优化阶段共同塑造表示。把三个阶段排成更聪明的顺序，并不能自动替代共同演化。

4.3 Vision Laziness：视觉惰性是什么

论文定义的视觉惰性（vision laziness）是：当语言主干在视觉加入前已经高度优化，模型更倾向依赖语言先验完成视觉任务，而不是充分使用和发展视觉路径。它不表示模型完全忽略图像，也不等同于一般意义上的训练不足；当前论文用四组内部测量刻画它：

  1. 训练期间，图像专用 FFN 输出的 L2 范数下降。L2 范数是把所有数值平方求和再开方，用来表示激活整体大小。
  2. 图像起止标记的嵌入范数下降，表明语言路径对图像片段的接纳减弱。
  3. 推理期间，图像专用 FFN 的单位元素激活下降。
  4. 生成时图像 token 对图像 token、理解时文本 token 对图像 token 的注意力比例下降。

四项测量都随语言预热从 0B 增加到 800B 而下降，并且视觉性能同步变差。这个相关链条支持“模型越来越少使用视觉路径”的解释。

不过，激活或注意力数值小不天然等于贡献小。更强的表示可能用更小范数完成同样计算，注意力权重也不是完整因果归因。论文通过多个指标的一致方向增强了可信度，但如果要证明视觉惰性是性能下降的唯一原因，还需要干预实验，例如强制提高图像注意力、屏蔽语言捷径或交换视觉路径后观察性能是否恢复。

5. Recipes：为什么最终是 70/25/5

作者在 1T-token 训练中搜索三类数据占比：语言 L、视觉理解 U 和视觉生成 G。先把视觉理解与生成等分、扫描语言占比；再固定语言占比，搜索两种视觉任务的比例。最好的综合配置是：

\[ L/U/G = 70\%/25\%/5\%. \]

这个结果符合前面的知识流方向：语言同时帮助两种视觉能力，理解又帮助生成，而生成对其他能力的直接回报有限。因此，预算应优先投向能向多个方向输出知识的训练流。

在 1T-token 搜索中，70/25/5 的视觉理解平均分为 38.5。Benchmarking Compositional Text-to-Image Generation with Dense Prompts（DPG-Bench） 是用密集、长文本提示检查组合图像是否遵循各项语义约束的基准，得分为 0.450；GenEval: An Object-Focused Framework for Evaluating Text-to-Image Alignment（GenEval） 是检查生成图像中的对象、属性、数量和空间关系是否满足提示的组合生成基准，得分为 0.237。二者越高越好，并且都是同组五个配比中的最好结果；它们不直接衡量单张图像的审美质量。只给生成 5% 数据并没有让这两项生成评测变差。

5.1 放大到 13.5B 混合专家模型与 2T token

混合专家模型（Mixture of Experts，MoE）是在每层准备多个可选择的计算子网络，每个 token 只激活其中一部分；“总参数”表示所有专家之和，“激活参数”表示一个 token 实际使用的部分。它不等同于把多个完整模型做集成。

放大实验使用 13.5B 总参数、每 token 激活约 1.5B 参数的 MoE，共 256 个专家，每个 token 选择 16 个。其中两个激活专家被固定为语言专用和视觉专用，其余 14 个动态路由。模型从头做早期统一训练，共处理 2T token。

论文比较四个系统，其中 Full 表示同时采用 70/25/5 数据比例、混合专家架构和从头联合训练：

系统数据比例架构视觉加入时机
Balanced Recipe50/25/25MoE从头联合
Dense Model50/25/253.5B dense从头联合
Late-Fusion50/25/25MoE训练 60% 后加入视觉
Full70/25/5MoE从头联合

Full 相比 Balanced Recipe，语言准确率从 52.86 提升到 54.31，视觉理解平均分从 41.42 提升到 43.08；生成只用了五分之一的 token，GenEval 仍从 0.467 提升到 0.482，DPG-Bench 从 0.676 提升到 0.689。生成验证损失从 0.261 变差到 0.272。

Fréchet Inception Distance（FID）比较真实图像与生成图像在一个视觉特征空间中的均值和协方差，越低通常越好；它衡量分布接近程度，不直接等同于提示遵循或单图审美质量。在 5 万张生成图上，FID 从 5.131 变为 5.234，表明少生成数据并非所有生成指标都更好。

与 dense 模型和晚统一模型的对照也支持专用 FFN 与早期联合训练。但这些不是完全等参数量的硬件效率比较：13.5B MoE 和 3.5B dense 的总容量、通信和显存需求不同，论文强调的是每 token 激活容量下的任务效果，不是证明 MoE 在任意集群上都更快。

5.2 不能把 70/25/5 当作普适常数

这个比例依赖至少六个条件：文本与图像数据质量、token 计数方式、生成目标、视觉 tokenizer、模型容量和评测权重。换成音频、视频、机器人动作或更强生成质量目标后，最优比例很可能变化。

更可复用的是搜索原则：

  1. 固定目标能力的绝对预算，单独增加另一种训练流，测量有方向的边际收益。
  2. 同时记录正迁移与负迁移，不能只看综合平均分。
  3. 用单模态基线区分“联合训练真的变好”和“只是总训练量更多”。
  4. 对共享组件做局部拆分，定位协同来自信息交换还是共享容量。
  5. 在固定总预算下比较训练时机，避免把更多计算误当成更好调度。
  6. 在小模型找到规律后，用单变量对照在更大规模复验。

6. 证据较强的结论与仍需验证的问题

6.1 证据较强的部分

知识流具有方向。 真实数据趋势在四种视觉表示中复现，CLEVR 又提供概念删除实验，二者共同支持“理解更容易帮助生成，生成很少直接帮助标准理解”的非对称性。

参数共享需要有边界。 五种组件共享方案在相同数据预算下比较，结果清楚地排除了“全部共享最好”和“全部拆分最好”两种简单答案。

固定预算下早统一优于晚统一。 多个视觉指标随语言预热增加呈一致下降，顺序训练与回放也没有追上联合训练；这一结论在论文设定内相当稳定。

非对称配方能放大。 1T-token 网格搜索得到的方向，在 13.5B MoE、2T-token 训练中仍然成立，而不是只停留在小模型现象。

6.2 仍需谨慎的部分

“物理学”仍是经验规律，不是自然定律。 论文没有给出可从第一原则推导的方程，也没有证明跨模型、跨模态的普适不变量。标题里的 physics 更接近“寻找稳定现象与机制”。

视觉惰性还不是完整因果解释。 四项内部指标与性能共同下降很有启发，但缺少直接恢复视觉路径的干预实验。

复杂度没有统一度量。 从纯色背景到自然图像的阶梯直观合理，却不能直接用于给任意数据集排序。

统计不确定性披露有限。 多数受控实验固定单个随机种子，表格没有置信区间；很小的差值需要复现实验才能判断稳定性。

模态范围仍窄。 论文主要研究文本和静态图像。作者也明确把音频、视频和超大规模模型列为未来工作。视频包含时间依赖，音频同时包含语义、说话人和韵律，知识流可能出现新的方向。

数据来源影响外推。 视觉训练主要来自同一个商业图文数据源；文本风格、版权条件和图像分布变化后，竞争与协同的边界可能移动。

7. 对原生全模态模型研究的直接启示

Omni 模型是原生处理并生成多种模态的模型，例如同时接收文本、图像、音频和视频，并输出文本、语音或图像；这里不把简单调用多个外部专用模型的流水线算作原生 Omni 模型。

如果把论文的方法迁移到 Omni 训练，我会先画一张更大的有向图，而不是先猜数据比例：文本是否帮助语音生成，语音识别是否帮助说话人理解，视频理解是否帮助视频生成，音频生成是否为情绪识别留下潜在先验。每条边都应分别测试零样本能力和微调后的学习速度。

架构上，可以把共享注意力视为跨模态交换通道，把模态专用 FFN 或专家视为容量隔离区。但音频和视频序列远长于单张图像，共享全注意力的计算成本可能不可接受；此时应研究分层或稀疏的信息交换，而不是机械复制本文结构。

训练时机上，早统一的核心不是“第一步就加入全部高成本数据”，而是不要让某条强模态在其他路径出现前完全固化。可以在低分辨率、低帧率或低采样率上早期接入，再逐步提高保真度，这仍保留共同演化，同时控制计算量。

评测上，要把“生成对理解没有直接帮助”拆成更细问题。标准问答可能只需要稀疏语义，而空间、物理、韵律和情绪任务需要密集表示；生成训练的价值可能主要体现在这些任务的样本效率，而不是通用排行榜的零样本分数。

8. 结论

这篇论文提供了一套值得继续检验的设计思路：先测清楚知识从哪里流向哪里，再用专用容量隔离竞争、用共享通道保留协同，并让各种模态从训练早期共同演化；数据预算应优先给那些能够向更多能力输出先验的训练流。
